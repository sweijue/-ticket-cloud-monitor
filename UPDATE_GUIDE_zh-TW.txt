V3.5 電腦 / SE2 共用管理版

這是原本 V3.4 Railway 專案的更新包，不是獨立新專案。
不要清空 GitHub、不要重建 Railway 或 Volume。

1. 更新管理頁
在原 GitHub 專案覆蓋 / 新增以下四個檔案：
server.js
public/app.js
public/index.html
public/ticketplus-linked.user.js  (新增，也是電腦和 SE2 要安裝的腳本)
保留原本 package.json、Dockerfile、public/style.css、Volume。
本版不新增 npm 依賴。已設定的 MIN_SECONDS=1 可保留。
Commit 後等 Railway 部署成功，管理頁會顯示 V3.5。

2. 原本遠大監控不用重建
先停止遠大這筆。網址必須是已知可登入讀票種的 /order/ 單場網址。
不能用活動首頁或 PDF。名稱、頻率、時段、ntfy Topic 保留在這筆。
按「配對電腦 / SE2」，這筆就會改成本機瀏覽器模式，Railway 不再同時抓它。
複製 tcm1. 開頭的配對碼。同一份可供兩台裝置使用。
不要為第二台重按產生：重新產生會使舊碼失效。
配對碼可控制這筆監控，請當成密碼保管，不要貼到對話或公開截圖。

3. Windows 和 SE2 使用同一支腳本
Windows: 在 Chrome / Edge 安裝 Tampermonkey，匯入 public/ticketplus-linked.user.js。
SE2: 把同一檔案放入 Userscripts 指定資料夾，開啟 Safari 延伸功能並允許遠大網站。
請停用 / 移除舊「SE2 Ticket Plus Monitor 1.0.0」腳本，不要同時開啟兩版。
本腳本只對 ticketplus.com.tw 執行，只允許連到 ntfy.sh 和你目前的 Railway 網域。
目前管理頁網域是 ticket-cloud-monitor-production.up.railway.app。
若將來更換網域，腳本 LINK_ORIGIN 和 @connect 必須同步修改。

4. 在售票頁配對，不是在 Railway 頁執行腳本
用該台裝置的瀏覽器登入遠大的單場票種頁。
打開「監票」面板，展開「連到原本的管理頁」。
裝置名稱填 Windows 或 SE2，貼上同一組配對碼，按「配對」。
按「讀取票種」，勾選票種、核對狀態，按「儲存票種到管理頁」。
名稱、頻率、排除特殊席、時段、Topic 由管理頁統一設定。
先測試通知，確認接收端真的收到，再在票種頁按「開始監控」。
管理頁會在原卡片顯示裝置名稱、回報時間、票種和檢查結果。

5. 從電腦換到 SE2
先在 Windows 的票種頁按停止。
在 SE2 的票種頁配對相同監控（只需一次），按「同步共用設定」。
讀取票種、核對後按開始。確認管理頁顯示 SE2 回報後，才關電腦。
這是手動接手，不是電腦關機就能自動喚醒手機。
同一筆同時只允許一台裝置回報和刷新。斷線後約 60 秒內會改為等待裝置。
若看到「另一台正在執行」，先停止舊裝置，不要重複重新配對。
裝置看起來在線是指最近 60 秒內有回報，不是即時電源偵測。

重要限制
- 本機動作仍需電腦開機、瀏覽器開著、票種分頁在前景。SE2 需保持前景不鎖屏。
- 管理頁不需在執行裝置開著；你可用另一台手機查看。
- 目前接通的本機站點僅 Ticket Plus /order/。拓元、KKTIX 不會因此自動解除 403。
- 沒有實作自動雲端到本機切換，不會自動開啟售票分頁或登入。
- 1～5 秒是每次讀取和回報完成後的等待，不保證每秒完成一次。仍可能觸發網站限制。
- 遇到登入、驗證、排隊或無法辨識票種會停止，不繞過防護。
- 登入 Cookie、密碼、票務權杖不會匯出或上傳。配對只傳票種設定和觀測狀態。
- 有票時先停止刷新，再由管理端發 ntfy；實際送達速度以手機和 Windows 通知設定為準。
- 如果管理頁失聯，本機停止刷新，不會在失聯時繼續單獨暴衝請求。
- 管理頁按停止後，本機會在下次心跳或刷新前確認後停止。已送出的網頁請求不能回收。

目前完成的是程式和本機模擬測試。仍需在你真正登入後的頁面核對票種；沒有取得你的帳號存取權。
